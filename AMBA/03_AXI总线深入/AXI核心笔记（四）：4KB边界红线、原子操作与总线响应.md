# AXI 核心笔记（四）：4KB 边界红线、原子操作与总线响应

> **定位**：芯片原厂驱动编写 Scatter-Gather DMA、配置外设 MMIO 以及排查 Linux 内核 Asynchronous External Abort 的根因手册。

---

## 1. 致命红线：为什么单次 Burst 绝不能跨越 4KB 边界？

### 1.1 协议规定
AXI 规范严禁任何突发传输（Burst）跨越 **4KB 物理地址边界**（即 `addr[11:0] = 0x000` 的位置）。

### 1.2 硬件底层本质原因（芯片设计机制）
1. **从机地址译码边界**：在 SoC 片上互联总线（NoC / Interconnect）中，地址译码器的最小粒度通常就是 **4KB**。
   * 地址 `0x1000_0FF0` 可能属于芯片内部的 SRAM；
   * 地址 `0x1000_1000`（跨越了 4KB）可能被配置映射给了一个完全不同的外设（如 UART 或看门狗）。
2. **硬件不会在 Burst 中途重新译码**：
   * AXI 在突发传输开始时，**只发送一次起始地址 (`AWADDR` / `ARADDR`)**，后续的连续数据传输全靠从机内部的累加器自动递增；
   * 如果跨越了 4KB 边界，互联总线无法在突发中途动态切换片选与路由，会导致后半段数据被错误地写入另一个从机，或直接踩进无映射死区触发硬件硬故障（DECERR）。

### 1.3 驱动层对策（Scatter-Gather 切片）
编写 DMA 驱动时，如果上层下发一个 8KB 的大块内存，且起始地址不是 4KB 对齐（例如 `0x8000_0800`，长度 8192 字节）：
* **严禁一次性填入 DMA 描述符！**
* 驱动必须将其拆分成两笔（甚至三笔）描述符：
  * 第一笔：`0x8000_0800 ~ 0x8000_0FFF` (长度 2048B，恰好到达 4KB 边界)；
  * 第二笔：`0x8000_1000 ~ 0x8000_27FF` (长度 6144B，后续连续空间)。

## 2. 原子操作与排他访问 (Exclusive Access)
在多核 CPU 运行操作系统（如 Linux 互斥锁、自旋锁、原子变量 `atomic_t`）时，依赖总线层面的原子性支持。
* **信号支持**：`ARLOCK[0]` / `AWLOCK[0]`（AXI4 简化为 1-bit 排他标志）。
* **交互流程 (以 LDREX / STREX 为例)**：
  1. **Exclusive Read (排他读)**：CPU 发起带 `ARLOCK=1` 的读请求，总线监视器（Exclusive Monitor）记录该 Master 的 ID 与访问地址范围；
  2. **Exclusive Write (排他写)**：CPU 运算完毕后发起带 `AWLOCK=1` 的写请求；
  3. **结果判定**：
     * 若此期间没有其他 Master 更改过该地址，写操作成功，从机返回 `BRESP = EXOKAY (0b01)`；
     * 若已被他人修改，写操作被拦截取消，从机返回 `BRESP = OKAY (0b00)`，CPU 指令返回失败并重新循环重试。

## 3. 总线响应状态与故障定性 (`RRESP` / `BRESP`)

AXI 规定了 2-bit 的响应状态编码：

| 编码 | 响应名称 | 含义 | Linux 内核映射与排查方向 |
| :--- | :--- | :--- | :--- |
| `0b00` | **OKAY** | 正常成功 | 传输无误。 |
| `0b01` | **EXOKAY** | 排他访问成功 | 原子操作成功完成。 |
| `0b10` | **SLVERR** (Slave Error) | **从机内部错误** | 访问命中从机，但从机拒绝（如只读寄存器强行写、未初始化、奇偶校验/ECC 错误）。 |
| `0b11` | **DECERR** (Decode Error) | **地址译码错误** | 请求的物理地址根本**不存在**（没有挂任何 Slave，踩入片上未映射黑洞）。 |

* **排查提示**：当 Linux 发生 `Unhandled fault: synchronous/asynchronous external abort` 时，查看打印的 `FAR (Fault Address Register)`，若地址完全不在芯片 Memory Map 范围内，100% 为 **DECERR**；若地址在正确的外设范围内但外设时钟未开，通常为 **SLVERR**。
