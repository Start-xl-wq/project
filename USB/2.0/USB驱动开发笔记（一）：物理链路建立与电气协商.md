**标签：** `#USB驱动` `#物理层` `#底层硬件` `#Chirp握手`

在真正发送 USB 数据包之前，Host 和 Device 必须通过底层的 D+/D- 引脚完成**插入检测**、**速度识别**以及**底层时钟同步**。这个过程完全由硬件（USB PHY）完成，是驱动开发中排查“设备无法识别”等硬件连通性问题的基础。

---

## 1. 物理引脚与“空闲”状态 (Idle State)

标准 USB 2.0 包含 4 根线：`VBUS (5V)`、`GND`、`D+`、`D-`。数据传输依赖 D+/D- 这对**差分信号线**。

- **Host 侧默认状态**：Host 在 D+ 和 D- 上各下拉了一个 **15kΩ 的电阻**到地。
- **SE0 状态 (Single-Ended Zero)**：在未插入设备时，D+ 和 D- 的电平都被拉低至约 0V。这种 D+ 和 D- 同时为低电平的状态称为 **SE0**。
- **判断依据**：只要 Host 持续检测到 SE0，即认为“总线上无设备挂载”。

---

## 2. 插入检测与初始速度识别 (Attach)

设备插入并获得 VBUS 供电后，必须通过**上拉电阻**向 Host 宣告自己的存在及速度类型。Device 端通常通过一个 **1.5kΩ 的上拉电阻**（拉至 3.3V）来实现。

- **低速设备 (Low-Speed, 1.5Mbps)**：1.5kΩ 上拉电阻接在 **D-** 上。
- **全速设备 (Full-Speed, 12Mbps)**：1.5kΩ 上拉电阻接在 **D+** 上。

> **⚠️ 核心重点：高速设备 (High-Speed, 480Mbps) 的伪装** USB 2.0 规范中**没有**为高速设备设计独立的上拉引脚。所有高速设备在初始插入时，**必须先伪装成全速设备**（将 1.5kΩ 电阻接在 D+ 上），后续再通过 Chirp 协议切入高速。

---

## 3. USB 的电气状态字母表 (J / K / SE0)

USB 通信不使用简单的 0V/3.3V 代表逻辑 0 和 1，而是定义了特定的差分状态组合（以全速/高速设备为例）：

1. **SE0**：`D+ = 低`，`D- = 低`。用于表示总线断开、复位(Reset) 或 包结束(EOP)。
2. **J 状态 (J-State)**：`D+ > D-`（D+为高，D-为低）。全速设备空闲时（D+被上拉）即处于 J 状态。
3. **K 状态 (K-State)**：`D- > D+`（D-为高，D+为低）。

_(注：低速设备的 J/K 极性与全速设备完全相反，开发 USB 2.0 默认不关注低速)_

---

## 4. 信号编码机制 (NRZI & Bit Stuffing)

为了解决没有独立时钟线 (CLK) 导致的数据同步问题，USB 在物理层采用了特殊编码：

- **NRZI 编码 (Non-Return-to-Zero Inverted)**：
    - 发送数据 `0`：电平**翻转**（J变K，或K变J）。
    - 发送数据 `1`：电平**保持不变**。
    - _目的：利用发送 `0` 时的电平跳变沿，让接收端同步内部时钟。_
- **位填充 (Bit Stuffing)**：
    - _问题_：如果连续发送一串 `1`，电平一直不翻转，接收端时钟会跑偏。
    - _机制_：发送端 PHY 硬件若检测到**连续发送了 6 个 `1`**，会自动在总线上**强行插入一个 `0`**（制造一次翻转）。接收端 PHY 收到 6 个 `1` 后的 `0` 会自动将其剔除。
    - _注意_：此过程由硬件 PHY 自动完成，驱动软件层完全无感。

---

## 5. 核心机制：高速握手 (Chirp Handshake)

这是设备从 12Mbps 全速切换到 480Mbps 高速的决定性流程，包含 4 个严格的步骤：

1. **Host 发起复位 (Bus Reset)**：
    - Host 强行将总线拉入 **SE0 状态**。规范要求至少维持 10ms。
    - Device 底层 PHY 检测到持续 >2.5us 的 SE0，确认接头开始。
2. **Device 发起宣告 (Chirp K)**：
    - Device 在 Reset 期间，向总线注入一个持续 1ms ~ 7ms 的 **K 状态 (Chirp K)**。
    - 作用：Device 告诉 Host “我支持高速模式”。发送完毕后 Device 恢复静默。
3. **Host 回应序列 (Chirp K-J 翻转)**：
    - Host 识别到 Chirp K 后，若自身也支持高速，会向总线发送交替的 K 和 J 状态：**Chirp K -> Chirp J -> Chirp K -> Chirp J ...**
4. **电气切换，切入高速 (The Big Switch)**：
    - Device 监听到**至少 3 对连续的 K-J 翻转**后，确认握手成功。
    - **硬件动作**：Device 立即**断开** D+ 上的 1.5kΩ 上拉电阻，同时 Host 和 Device 双侧自动挂载 **45Ω 对地终端电阻**。
    - **结果**：通信电平幅度从全速的 3.3V 骤降至 **400mV**，总线正式进入 480Mbps 高速模式，Reset 结束。

---

## 6. 总线电源管理 (Suspend & Resume)

- **挂起 (Suspend)**：若 Host 连续 **3ms** 未在总线上发送任何信号（维持空闲 J 状态），Device 的 PHY 会触发 Suspend 中断，驱动需控制芯片进入低功耗状态。
- **唤醒 (Resume)**：Host 欲唤醒设备时，会在总线上发出持续 20ms 的 **K 状态**信号，设备检测后退出低功耗模式。

---

## 7. 💡 总结推演：从插入到 480Mbps 的完整时间线

当面试官提问：“一根 USB 线插上后，底层发生了什么？”标准推演链路如下：

1. 设备上电，D+ 挂载 `1.5kΩ` 上拉电阻。
2. Host 检测 D+ 变高，总线进入 `J 状态`，识别到**全速设备**接入。
3. Host 发出至少 `10ms` 的 `SE0` 状态，发起 **Bus Reset**。
4. Device 侦测到 SE0，主动发出 1~7ms 的 **Chirp K** 信号，宣告支持高速。
5. Host 回应交替的 **Chirp K-J-K-J-K-J** 序列。
6. Device 侦测到 3 对 K-J 后，**断开 1.5kΩ 上拉，切入 45Ω 终端电阻**。
7. 通信电平降至 400mV，高速链路 (480Mbps) 物理层建立完成！
