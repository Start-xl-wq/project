# U2/U3 测试模式

以 Linux DWC3 控制器为例，说明 Device / Host 如何进入发送端电气测试模式，以及 USB3 Gen1 如何切换 CP 码型。命令已对照 DWC3 / xHCI 驱动核对，AX8860 实板出波及 AUX/CAL OUT 切码效果尚待验证。

## 1. 准备

板端使用 root，通过独立串口或网络操作；测试会中断正常 USB 通信。接好对应速率的测试夹具与示波器，确认控制器角色及 PHY 初始化状态。

内核需启用 debugfs，并提供对应的调试接口。若尚未挂载 debugfs：

```sh
mount -t debugfs none /sys/kernel/debug
ls /sys/kernel/debug/usb/
```

下文 DWC3 目录以 `2e1f0000.dwc3` 为例，其他平台替换为实际名称。

## 2. U2 Device：TEST_PACKET

控制器处于 Device 模式，使用 USB2 High-Speed（480 Mb/s）测试连接：

```sh
echo test_packet > /sys/kernel/debug/usb/2e1f0000.dwc3/testmode
cat /sys/kernel/debug/usb/2e1f0000.dwc3/testmode
```

**预期效果：**读回 `test_packet`，D+/D− 输出重复测试包，可采集 480 Mb/s 眼图。

如需测静态电平，分别使用 `test_j` 或 `test_k` 替换 `test_packet`；采集数据眼图仍使用 `test_packet`。

## 3. U3 Device：Compliance

USB3 PHY 已初始化，控制器处于 Device 模式且满足驱动的 SuperSpeed 条件时执行：

```sh
echo Compliance > /sys/kernel/debug/usb/2e1f0000.dwc3/link_state
cat /sys/kernel/debug/usb/2e1f0000.dwc3/link_state
```

**预期效果：**读回 `Compliance`，SSTX+/SSTX− 输出 Compliance 测试码型，Gen1 速率为 5 Gb/s。

若返回 `Invalid argument`，检查角色、SuperSpeed 条件和大小写。仅接上无源夹具不保证满足这个软件入口的条件。状态读回不能识别具体 CP 编号，需同时检查实际波形。

## 4. U3 Host：xHCI 端口 Compliance

DWC3 处于 Host 模式时，通过其 xHCI 子控制器操作 USB3 硬件端口：

```sh
ls /sys/kernel/debug/usb/xhci/*/ports/*/portsc
```

xHCI 目录名通常为 `xhci-hcd.N.auto`，不应直接套用 DWC3 的 `2e1f0000.dwc3`。确认端口对应被测连接器的 USB3 部分，不要默认 `port01` 就是目标端口。

将占位符替换为实际路径，端口处于 `RxDetect` 时执行：

```sh
USB3_PORTSC='/sys/kernel/debug/usb/xhci/<控制器名>/ports/portNN/portsc'
cat "$USB3_PORTSC"
echo compliance > "$USB3_PORTSC"
cat "$USB3_PORTSC"
```

**预期效果：**配合测试连接进入 Compliance，状态显示 `Compliance mode`，SSTX+/SSTX− 输出测试码型。

Host 的 `compliance` 为全小写。若返回 `Operation not permitted`，检查端口状态。部分控制器已允许 Compliance 转换，该写操作可能不修改寄存器，仍需满足实际测试连接条件；不能只凭命令未报错判断进入成功。

## 5. U3 Gen1：用 DSAV204A + U7242-66501 切换 CP

首次进入 Compliance 从 CP0 开始。每收到一次有效 Ping.LFPS，推进一个 CP 码型；没有切换触发时持续发送当前码型。

示波器需安装支持该机型的 USB Compliance 软件。以下按 U7243 系列的 `Toggle` 流程说明，菜单和输出口以实际软件版本的连接图为准。

```text
板子 SSTX± ── U7242-66501 ──→ 示波器采集通道
板子 SSRX+ ←─ U7242-66501 ←── 示波器 AUX/CAL OUT
```

1. 按板子角色选夹具的 Host 或 Device 测试区，按软件连接图配置输出口、其余端接及附件。U7242-66501 本身不主动产生 Ping.LFPS。
2. 按上面的 Device 或 Host 步骤进入 Compliance，确认能够采到发送波形。
3. 运行 USB Compliance 测试，在要求切换 CP0/CP1 的提示窗口点击 `Toggle`。
4. 板子成功响应一次，就推进一个码型。从 CP0 推进一次为 CP1；实际波形与目标参考波形一致后，点击 `OK` 继续测试。

**预期效果：**CP0 的伪随机数据波形变为 CP1 的规则周期波形，控制器仍显示 Compliance。

**点击后无变化：**先检查 AUX/CAL OUT 是否接到板子 RX，以及软件是否配置了对应输出。Keysight 的 AUX/CAL OUT 脉冲切换仅适用于部分 5 Gb/s Gen1 DUT，不能等同于标准 Ping.LFPS 信号源。AX8860 是否响应此方式尚待实测；接线及配置正确仍无响应时，使用支持标准 Ping.LFPS 的测试信号源。

当前核对的 DWC3 + Axera 驱动未找到直接选择 CP0/CP1 的软件接口；重复 `echo Compliance` 不用于切换码型或保证回到 CP0。

## 6. U2 Host：EHSET

U2 Host 使用 EHSET 测试夹具或支持 USB2 端口测试的工具。内核需启用 `CONFIG_USB_EHSET_TEST_FIXTURE`；连接并选择夹具的 TEST_PACKET 项，由驱动发起端口测试。

**预期效果：**Host 端口 D+/D− 输出 USB2 测试包，可采集 480 Mb/s 眼图。当前检查的驱动没有通用的 Host `echo test_packet` 入口，不可套用 Device 路径。

## 7. 结束测试

保存测试数据，通过独立控制通道重启板卡恢复正常工作。`echo device > mode` 不作为退出测试命令。

眼图判读和参数调节参见 [USB2 PHY 眼图](<USB2 PHY眼图调试及调优.md>)、[USB3 PHY 眼图](<USB3 PHY眼图概念及调优.md>)。
