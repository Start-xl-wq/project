# MMC / SD / SDIO 常见错误 (CRC / Timeout / 卡死) 原厂排查定位指南

> **定位**：芯片回片后出现“偶发读写失败”、“I/O Error”、“总线死锁卡死”的标准化排查树。

---

## 1. CRC 错误排查（CMD CRC7 vs DATA CRC16）

### 1.1 区别与判定
* **CMD CRC7 Error (命令校验失败)**：发生在主机发出的命令包或从机返回的响应包（Response）中。
  * **现象**：执行特定命令（如 `CMD1`、`CMD2`、`CMD8`）时驱动直接报错退出。
  * **根因**：CMD 走线阻抗突变、驱动能力不足导致上升沿变缓、或者板级电源瞬间跌落。
* **DATA CRC16 Error (数据校验失败)**：发生在多块数据传输（Read/Write Block）中。
  * **现象**：卡片成功识别，但一大文件读写（如 `dd` 跑压测）跑几分钟就报 `mmcblk0: error -84 transferring data`。
  * **根因**：高速模式下时钟相位跑偏（Tuning 窗口偏移）、温升漂移、走线间串扰。

### 1.2 解决手段
1. **优先调谐检查**：重新运行 Tuning 流程，打印有效窗口大小，核对当前工作相位是否偏离了中心；
2. **硬件驱动能力调整**：调整驱动参数中的 `drive-strength`（如从 8mA 调整为 12mA），改善上升沿斜率；
3. **降频保活验证**：在软件设备树中强制限制最大时钟（如将 200MHz 降至 100MHz 或 50MHz），若降频后故障立刻消失，100% 为信号完整性（SI）问题。

## 2. 数据超时错误 (Data Timeout / error -110)
* **表现**：Linux 内核报 `mmc0: Timeout waiting for hardware interrupt` 或 `error -110`。
* **排查重点**：
  * **卡端繁忙 (Busy / D0 拉低)**：在写入 Flash 后，eMMC 内部正在进行繁重的数据搬运与垃圾回收（GC），卡端通过持续拉低 `DAT0` 线告知主机处于 Busy 状态。
  * **超时阈值设置不合理**：控制器寄存器中的 `Data Timeout Counter` 设置的时间过短（例如设成了 10ms，而卡片极端情况下需要 250ms），导致控制器过早触发硬件超时中断。

---

## 3. 硬件总线死锁 (Card Hang / Bus Hang)
* **表现**：读写某个特定扇区时，驱动卡死在 `wait_for_completion`，整个系统 I/O 挂起。
* **排查方向**：
  * **ADMA 描述符 END 标志漏置**：硬件沿着链表读到底后未见 `END=1`，继续访问非法物理地址导致总线挂死；
  * **电源未稳定即发命令**：`VCC`、`VCCQ` 上电时间未达标，复位引脚释放过早，内部数字核状态机未就绪。
